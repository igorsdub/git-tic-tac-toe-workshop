Lesson 1: Mastering the Live Demonstration

Lesson: 0001 Topic: Co-Pilot Demonstration (Minutes 20–40) Mission: Facilitator Readiness

Welcome to your first facilitator lesson! In the Git Tic-Tac-Toe Workshop, the Live Demonstration is the pivotal bridge between conceptual understanding and learner execution. If the demo drags or confuses, learners get stuck. If it is crisp and visual, 100% of pairs will begin playing within two minutes of being released.

The Facilitator's Goal

Demonstrate Move 1 (Player X) and Move 2 (Player O) in under 20 minutes with a prepared co-facilitator or TA. Show side-by-side terminals and the GitHub web interface so learners visibly witness the remote handshake.

1. Technical Staging: Two Screens, One Board

Never perform the live demo alone by switching back and forth on one terminal. Novices cannot distinguish local branches from remote pushes if all commands run on one prompt.

  • Screen Left (Player X): Lead Facilitator's laptop or terminal.
  • Screen Right (Player O): Prepared Co-Facilitator or Teaching Assistant.
  • Browser Window (Middle): The repository page on GitHub.com displayed on the projector.

2. The Exact 4-Step Script

Step A: Handshake on GitHub (Minutes 20–24)

Player X creates the repository from the template igorsdub/tic-tac-toe-template and adds Player O under Settings > Collaborators. Player O confirms receipt and runs: 

git clone <repo-url>
cd <repo-folder>

Step B: Move 1 by Player X (Minutes 24–28)

Player X points out that git status is clean. Player X edits board.md, placing X in square 5 (center), and updates State: Waiting for O. 

git status
git diff              # Highlight: exactly one line changed!
git add board.md
git commit -m "Move 1: X in center square 5"
git push origin main

Facilitator Cue: Refresh the GitHub browser tab on the projector. Show the commit hash and Player X's commit message appearing on the remote.

Step C: Move 2 by Player O (Minutes 28–34)

Player O opens their local board.md on screen. Point out: it is still empty! Git does not magically push files across local hard drives. Player O must pull: 

git pull origin main  # Show square 5 instantly update to [X]!
# Player O edits square 1 to [O], updates State: Waiting for X
git add board.md
git commit -m "Move 2: O takes top-left square 1"
git push origin main

Step D: Closing the Loop (Minutes 34–38)

Player X runs git pull origin main to receive Move 2. Then, run the history inspection command: 

git log --oneline --graph

Highlight to the room: each move has an immutable author name, timestamp, and message. The board's entire evolution is preserved.
