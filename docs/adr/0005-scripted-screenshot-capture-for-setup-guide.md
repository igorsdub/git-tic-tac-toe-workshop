# 5. Scripted screenshot capture for the setup guide

## Context
The Setup stage for Codespaces workshops walks first-time users through GitHub's web UI: creating a repository from the template, creating a Codespace, using Copilot Chat, and stopping the Codespace. That UI changes often. Hand-made screenshots go stale and nobody remembers to retake them; text-only steps lose first-time users. A recorded walkthrough made by hand has the same staleness problem.

## Decision
Screenshots and per-stage videos in the setup guide are generated by a scripted Playwright capture (`scripts/capture/`) run against the facilitator's own GitHub account on a throwaway demo repository, with a persistent logged-in browser profile kept out of git. ffmpeg post-processes the recording into a per-stage video with zoom-ins at each click. Captures are committed under `docs/images/setup/` and regenerated before each workshop with one command.

Alternatives rejected:
- Text-only steps with links to GitHub docs: loses novices.
- Hand-made screenshots: go stale.
- A dedicated demo account: needs an extra 2FA device to maintain; it can be swapped in later by changing the profile directory.

## Consequences
The guide always matches the current GitHub UI, at the cost of a Node/Playwright dev dependency and a one-off manual login per machine. The facilitator's avatar and username appear in captures. Account signup itself cannot be captured on an existing account, so that step is text-only.

`scripts/capture/captures.json` is the manifest of step slugs and screenshot names; the capture scripts reject unlisted screenshots, and a test keeps it consistent with `docs/setup.html`.
