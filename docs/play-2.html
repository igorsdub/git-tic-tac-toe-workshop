Planner, then everyone else

The planner matters most. A wrong agreement here makes every later role build the wrong thing.

Skills, then grill the plan

A skill is a SKILL.md file the agent reads before it acts. That file format is called Agent Skills. Matt Pocock's grill-me skill is one of them. A pstack-style collection is a folder of those SKILL.md files you keep and reuse.

Paste this Grill Me prompt:

Interview me relentlessly about every aspect of this plan until we reach a shared understanding. Walk down each branch of the design tree, resolving dependencies between decisions one by one.

Talk: Software fundamentals for AI coding. Optional longer source: full walkthrough of Matt Pocock's AI coding workflow. He says implementation and review should never share a context, which is why the review happens in a fresh chat.

The order of the chats

  1. Planner. Paste the planner prompt. Agree the rules before any code.
  2. Implementer. Paste the implementer prompt.
  3. Reviewer, in a fresh chat. Implementation and review should never share a context.
  4. Docs writer. It updates README.md and AGENTS.md.

Run it, break it, restore it

  1. Ask Copilot, in Agent mode, to add test_board.py and pyproject.toml from the PRD.
  2. In the terminal, run uv run pytest.
  3. Break BOARD.txt on purpose: a lowercase mark, or a digit 0 where a letter O belongs.
  4. Run uv run pytest again and watch it fail.
  5. Restore the board and run uv run pytest once more.

Create branch rematch

main is sacred. Don't touch it. Create rematch from main on github.com, the same way the owner created match.

Use the branch dropdown again

On github.com, open the branch dropdown and create rematch from main. Leave main untouched. Then both of you open Codespaces on rematch. Run uv run pytest and see it pass before every commit on this branch.

Run the check before every commit

A pre-commit hook is a small program Git runs before it records a commit. In the Codespace, save this as .git/hooks/pre-commit and make it executable with chmod +x .git/hooks/pre-commit.

#!/bin/sh
uv run pytest

GitHub Actions can run the same tests on every push.

you can name the manifest, lock file, runner, and test module

Reproducibility

Someone else can rebuild the same check when the project records what it needs and the exact versions.

Four names in this project

  • Manifest: pyproject.toml says what the project needs.
  • Lock file: uv.lock records the exact versions.
  • Runner: uv builds the environment and runs the command.
  • Test module: pytest runs test_board.py.

Julia records the same idea in Project.toml and Manifest.toml. R records it with renv.
