Agentic Coding

In this section we will think about how to get what you expect from the model, so its output matches the plan in your head.

1 Grilling

Let Copilot interview you until you agree. Then the agreed plan goes into PLAN.md. Nothing gets built before that.

Let the agent interview you

Copilot is the model in this workshop. It can write files and put a website online, but it cannot see the plan in your head. If you only say "build it," it will guess. The guess is often a different piece of work from the one you meant.

Grilling closes that gap. You say the idea in ordinary words. Then you let the agent interview you. It asks one question at a time, and you answer. Each answer settles one choice: who it is for, what they should see, where the information comes from, and what must stay as it is.

When you and the agent would describe the finished thing the same way, you are aligned. Aligned means you both want the same result.

You do not need to know how to program. You do need to say what you want, and you can decide that while you answer. If you are unsure, say so. A question is there so you can choose. While you are still deciding, an honest "I have not chosen yet" is a complete answer.

Stay in one chat for the whole interview. If a question depends on a choice you have not made, say that, and decide the earlier choice first. Tell Copilot not to create or change any file until you say the plan is agreed.

One question at a time matters because a long list gets a hurried yes. A single question gets a real decision. If Copilot asks three things in one message, answer the first and ask it to hold the rest.

Agree with your partner as well

The interview is between you, your partner, and Copilot. Your partner has a picture of the result too. Before you send an answer, say it out loud and check that you both mean it. If you do not, that question is not finished. Send the answer you both mean. Do not send a compromise that neither of you actually wants, hoping Copilot will sort it out later.

Take turns at the keyboard. The person who is not typing listens for a word that could mean two things. "Score" might mean games won, or it might mean a list of every game. When a word can mean two things, ask Copilot to split it into its own question.

What agreement looks like

You are ready to write the plan when you can answer these without guessing:

  • What will exist when you are finished?
  • Who will look at it, and what will they see first?
  • Where does the information come from?
  • What are you leaving unchanged?

If you cannot answer one of those, that is the next question. Do not fill the gap yourself and call it a plan. Let Copilot ask, and answer in your own words.

How the conversation goes

Keep this order. Do not skip ahead to building.

  1. Say the idea in a few sentences, as you would to a colleague who was not in the room.
  2. Let the agent ask one question.
  3. Answer that question only. Then wait for the next one.
  4. Repeat until nothing important is still a guess. You and the agent should be able to say the same plan back to each other.
  5. Ask the agent to write that plan into PLAN.md.
  6. Read PLAN.md. Correct it before anyone builds anything.

If Copilot starts creating files, or describes a finished website, before you have agreed, stop it. Say that you want one question at a time, and that the plan comes first. You can say "not yet."

Here is the shape of a grilling conversation. These lines show the kind of question to expect. They are not a script, and they are not the task in the next section.

  • Agent: Should this show one result, or every result you have saved?
  • You: Every result.
  • Agent: Who are the two people it should compare?
  • You: The two of us.
  • Agent: What would you open at the end, to know it worked?
  • You: A page in the browser, with our names and the score between us.

Your real conversation will be longer. That is the point of grilling. The questions you answer now are the ones Copilot would otherwise answer for you.

The agreed plan goes into PLAN.md

When you agree, ask the agent to write the plan into a file named PLAN.md. Read it. If a sentence is not what you decided, say what to change, and read it again. That file is what you point back to if the later work leaves the plan.

This file is usually called a PRD (product requirements document), PRD.md, and PLAN.md is just the plain name we use here.

In plain words, the file should say what you are making, who it is for, what "done" looks like, and what must not change.

Aside: the grill-me skill

A SKILL.md file is a reusable set of prompts. A prompt is a message you give the model. You save the messages you want to use again, and you point the agent at that file, so you do not retype them in every chat.

The grill-me skill is one SKILL.md. It tells the agent to interview you about the plan, one decision at a time, until you share an understanding, and to wait until then before it builds anything. You can keep that instruction and use it on a later task, including a task from your own work.

2 Build the scoreboard

With your partner, make a website that shows the score between the two of you. You are done when that website is live on GitHub Pages. You do not need to know how to program. You grill the idea, then you let Copilot build it.

Create a separate new repository

Do this work in a new repository. Do not do it in the repository where you played. Leave BOARD.txt as it is. Do not commit anything to the game repository. That repository stays unchanged.

One of you creates the new repository. The other joins it.

  1. On GitHub, open github.com/new.
  2. Type a name you will remember. Choose Public.
  3. Tick Add a README file so the repository has a first file. A Codespace needs that.
  4. Select Create repository.
  5. Invite your partner, the same way you did for the game.
  6. Open a Codespace on the new repository, the same way you opened one for the game.

One of you drives the chat. The other reads each question and the plan.

Grill Copilot, starting from this message

Copy the address of the game repository, the one you played in. It is the address in the browser when that repository is open. The game repository is already public, which lets the new site read the games stored there as branches.

Paste the message below into Copilot. Replace <link to our game repo> with that address, and delete the angle brackets. Stay in this chat. Answer one question at a time, the way the grilling section describes. The message asks Copilot to walk you through the options before it builds anything. Let it.

I need a scoreboard for a tic-tac-toe repository where games are stored on different branches: <link to our game repo>. A website should show the scores between the two players. I want to host it on GitHub Pages. I'm not an expert: guide me through the options one question at a time before building anything.

When you agree, switch to Agent mode if you are not already there, and ask Copilot to write the plan into PLAN.md. Read the file. If it does not match what you agreed, say what is wrong and ask for a change. Do not start the website until PLAN.md says what you decided.

Let Copilot build the website

GitHub Pages is GitHub's way of publishing a website from a repository. When it is on, GitHub gives you an address you can open in a browser.

Ask Copilot to build the website from PLAN.md and to turn GitHub Pages on. The site reads the games stored as branches in your game repository and shows the score between the two players.

If Copilot offers a choice, answer it. If it starts to edit BOARD.txt, or to change the game repository, tell it to stop. Those stay as they are. Every new file belongs in the new repository. You do not have to repair files yourself. Describe what you see, and ask Copilot to try again.

A live page is the end

Open the Pages address. GitHub shows it in the new repository under Settings, then Pages. You are done when that page loads and shows the score between the two players.

If the page does not load, tell Copilot what you see and ask it to fix the Pages setup. Keep PLAN.md as the plan you already agreed.

3 A task from your own work

Each person does this alone. You do not have to build it today.

Think of a task from your own work that you could grill an agent on. It might be a figure, a table, a protocol, or a piece of writing. Picture the questions you would want the agent to ask before it started, and what you would want written into a PLAN.md so the result matched the plan in your head.
